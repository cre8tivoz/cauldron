## Findings and independent design implications

1. **Architecture — partially answered.** Tauri IPC wrappers separate the frontend from native project/filesystem operations, including schema discovery, watching, note writes, recovery, Git and server management (offsets 542533–547017). Native binary strings also identify Tauri and Rust components; this is not an Electron implementation. **Cauldron:** define narrow project-scoped service interfaces; do not infer native enforcement from frontend wrappers alone.
2. **Collections/schema — partially answered.** The frontend invokes `read_astro_schemas` with project root and tracks synced/stale field metadata, showing an update-field-types action when stale (1897006, 2019521). Its UI suggests Astro sync for exact field types (2228854). The bundled validation code checks types including dates, arrays and objects and required object keys, with actionable errors (around 493658). There is a separate targeted frontmatter update IPC operation (543673). **Cauldron:** represent schema provenance/freshness explicitly, offer typed fields with useful fallback and errors, and preserve unrelated document data. Native schema parsing and full form coverage were not recovered.
3. **External edits — partially answered.** A file-watch event routes changed paths to a reread of open Markdown/text documents (1883951, 1885314); clean buffers are refreshed, while divergent dirty buffers create per-path mine/theirs conflicts. The conflict dialog states that keeping mine overwrites disk and using disk replaces editor content (2265602). Dirty detection compares editor text against a stored baseline (1856867). **Cauldron:** keep a baseline, preserve both versions and require an explicit choice; independently implement a compare-before-write or atomic concurrency guard, because frontend watch logic alone cannot establish race-free native writes. Rename/delete and all save-path edges were not fully traced.
4. **Recovery — partially answered.** A 10-second interval backs up dirty active content through recovery IPC, storing timestamp, original path, vault, text, filename and reason; matching disk content is discarded when recovery is reconciled (1880891). **Cauldron:** checkpoint drafts outside the content file, distinguish recovery from publishing, and clear only after verified save.
5. **Preview process — partially answered.** A frontend start flow chooses a project package manager, calls native start, polls every 600 ms, takes the reported port to form a localhost URL, and distinguishes starting, ready, stopped and failure (1916743). **Cauldron:** use an explicit state machine, structured log/exit diagnostics and cancellation generations. Native subprocess arguments, ownership, port selection and cleanup cannot be established from this frontend alone.
6. **Git — partially answered.** Before pull or publish, the frontend flushes and blocks if tabs remain dirty; pull subsequently rereads changed paths and refreshes relevant config/data/index state (2041747). Publish obtains status and can select paths inside the content boundary, including original rename paths, before invoking native sync (2057031–2057891). **Cauldron:** make dirty-buffer gating, scope selection and operation results explicit; independently verify Git operations and never imply atomic safety or stash behaviour from wrappers.

## Limits and handling

This is static shipped-artifact evidence, not observed runtime execution or a native decompilation. REA's JavaScript graph is partial and Electron-specific zero counts do not mean Tauri IPC is absent. Ghidra/Hopper providers were unavailable; no configuration or decompiler was installed. The exact native write atomicity, race protection, Git commands, schema extraction and process cleanup remain unknown. Recovered proprietary frontend is research evidence only: do not copy code or assets into Cauldron; independently implement the design lessons. `evaluation/rea-zeku/` contains proprietary-derived excerpts and a large REA graph; keep it out of version control. The workspace currently has no discoverable Git repository at the supplied root or project path, so ignore status could not be verified.
